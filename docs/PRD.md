# 重复文件清理工具 · 产品需求文档（PRD v1.0）

| 项目 | 内容 |
| --- | --- |
| 产品代号 | DupClean（暂定） |
| 定位 | Windows 本地、免安装、双击即用的重复文件清理工具 |
| 目标平台 | Windows 10（1607 及以上）/ Windows 11，x64、ARM64 |
| 交付形态 | 单个 .exe 文件，绿色单文件，无需 .NET/VC++ 运行时、无需管理员权限、无需联网 |

## 0. 一句话定义与目标

**一句话定义**：扫描用户指定的文件夹或整块磁盘，把「内容完全相同」的文件聚成一组，让用户用可组合的规则一次性决定保留哪一份、批量删除其余副本，且所有删除都可还原。

**核心目标**
1. 判定结果可信：默认「强一致」模式，接近 100% 不误判；任何低于强一致的判断都必须显式标注置信度。
2. 删除动作安全：默认进回收站、每组强制至少留一份、删除前可预演、操作可回溯还原。
3. 批量决策高效：把「按文件夹名长短 / 文件名长短 / 路径长短 / 日期新旧」等偏好变成可排序的规则链，一次点击作用于全部重复组。
4. 大磁盘可用：百万级文件、TB 级数据下可暂停、可续扫、可取消，不卡死界面。

**非目标（v1.0 不做）**
- 相似图片 / 近似视频 / 相似文档的内容感知去重（容易误判，放 v2.0 并单独分区）。
- 云端同步、账号体系、多设备同步。
- 直接清理系统盘的系统文件、注册表、软件缓存（这不是本工具职责）。
- 磁盘碎片整理、空间分析可视化（可留作后续扩展）。

## 1. 用户与场景

**主要用户**：非技术背景的办公人员（市场、销售、行政），磁盘里堆积了多年的资料、展会物料、客户报价、下载附件、微信/邮件接收的副本。

**典型场景**
- D 盘 5 年资料，`2023方案.pptx`、`2023方案(1).pptx`、`最终版-2023方案.pptx` 分散在 6 个目录，内容一模一样。
- 从网盘/微信反复导出，文件名被改得完全不同，但字节内容相同。
- 备份盘与工作盘互为镜像，需要清掉备份盘里的副本但保留工作盘目录结构。
- 同一个文件在 `项目A/共享/` 与 `项目B/归档/` 各有一份，文件名相同、路径不同。

**用户核心诉求排序**：不误删 > 别让我一个个点 > 看得懂为什么判为重复 > 快 > 界面好看。

## 2. 核心概念与术语

| 术语 | 定义 |
| --- | --- |
| 内容指纹 | 由「文件大小 + 强哈希 +（可选）逐字节比对」构成的判定依据，**不含文件名、时间戳、路径、EXIF 等元数据** |
| 重复组 | 内容指纹相同的 N（N≥2）个文件构成的集合。文件名相同与否只作为组内标签，不参与分组 |
| 主保留项 | 每组中由规则链选出的、必须留下的那一份 |
| 删除候选 | 组内除主保留项外的其余文件 |
| 可释放空间 | Σ(每组文件大小 × (N−1))，注意硬链接特殊处理（见 9.1） |
| 强一致 | L4 级别：大小相同 + 全文件哈希相同 + 逐字节比对通过 |
| 规则链 | 一组有序的「保留偏好」，按顺序决胜，用于从 N 个副本中挑出唯一保留项 |

**分组数据结构（示例）**
```
Group #0137  | 指纹 SHA256:9f2c...  | 大小 24,718,336 B | 4 份 | 可释放 74.2 MB
├─ D:\市场部\2024展会\方案最终版.pptx            创建 2024-03-02  路径长 34  [同名]
├─ D:\市场部\2024展会\备份\方案最终版.pptx        创建 2024-03-02  路径长 39  [同名]
├─ D:\临时\微信接收\方案最终版(1).pptx           创建 2025-11-07  路径长 30
└─ E:\归档\旧项目\a7f31.pptx                    创建 2022-08-19  路径长 21
```
> 分组键只有内容。第 1、2 项「同名不同路径」与第 4 项「异名」被正确合并在同一组，同名只作为 UI 标签与规则输入。

## 3. 功能需求

### 3.1 扫描范围 F-01
- 支持多选文件夹、整块磁盘（含 U 盘/移动硬盘）、拖拽目录到窗口。
- 支持「包含/排除」通配符或正则：扩展名（`.tmp`、`.log`）、目录名、文件路径、大小区间（如 <1KB 跳过，>4GB 单独提示）。
- 支持最小文件大小阈值（默认 1 KB，避免把海量零碎小文件拖进结果）。
- **默认排除（可手动解除，需二次确认）**：
  - `C:\Windows`、`C:\Program Files*`、`%AppData%`、`%LocalAppData%`
  - `$Recycle.Bin`、`System Volume Information`、`pagefile.sys`/`hiberfil.sys` 等系统文件
  - 符号链接、目录联接（junction、reparse point）：**默认不跟随**，仅记录，避免循环扫描与误删源目录
- 只读/无权限/被占用/加密（BitLocker 未解锁）文件：跳过并计入「无法访问」报告，不中断扫描。
- 云同步占位文件（OneDrive / 企业网盘 dehydrated 文件）：默认跳过或提示，避免哈希时触发全量下载。

### 3.2 判重判定体系 F-02（本产品的技术核心）

采用**分级漏斗**，每一级只把「有可能重复」的候选交给下一级，避免对全盘做全量哈希：

| 级别 | 判定方式 | 结论 | 用途 |
| --- | --- | --- | --- |
| L0 | 路径枚举、建立索引 | 元数据集合 | 统计文件数、大小分布 |
| L1 | **文件大小分桶** | 大小唯一 → 直接判定为「不重复」 | 淘汰 80%+ 文件，几乎零 IO |
| L2 | **三段采样哈希**：头部 64 KB + 中部 64 KB + 尾部 64 KB（BLAKE3 或 SHA-256） | 采样不同 → 判定不重复 | 大文件快速排除 |
| L3 | **全文件哈希**：分块 1–4 MB 流式计算 SHA-256（可选 BLAKE3 加速） | 哈希不同 → 判定不重复 | 高置信判重 |
| L4 | **逐字节比对**（byte-for-byte） | 全部相同 → **强一致** | 删除前的最终确认 |

- **关于「100% 相同」的产品表述**：哈希碰撞在理论上存在（SHA-256 碰撞概率远低于硬件出错概率），因此对外承诺「100% 相同」必须依赖 L4 逐字节比对。**默认在「加入删除队列前」对同组文件执行 L4**；用户可在设置中关闭 L4 换取速度，此时结果统一标注为「高置信（未逐字节校验）」，并在删除确认页再次提示。
- 提供三种预设模式：
  - **严格模式（默认）**：L1→L2→L3→L4，结果 100% 可靠。
  - **均衡模式**：L1→L2→L3，跳过 L4，适合百万文件的初筛。
  - **快速模式**：L1 + 文件名/大小启发式，仅用于「同名同大小」粗筛，结果**明确标注不可直接删除**，需升级为严格模式复核。
- 判定忽略项（写入 UI 说明）：文件名、扩展名、创建/修改时间、读写属性、所有者、NTFS  ADS 之外的元数据。
- 同名但内容不同 → **绝不合并成组**，可在「同名冲突」独立视图中查看（避免用户误解）。

### 3.3 分组与展示 F-03
- 结果按「重复组」列表呈现，可按可释放空间、文件数、扩展名、目录、组内是否同名排序/筛选。
- 组内表格列：缩略图/图标、文件名、所在文件夹、完整路径、大小、创建时间、修改时间、路径长度、文件名长度、目录名长度、路径层级深度、所在磁盘、硬链接标记、同名标记、匹配依据（L4/高置信）。
- 支持「展开全部 / 折叠全部」、组内搜索、跨组多选、按目录树着色。
- 顶部总览：扫描文件数、重复组数、冗余文件数、预计可释放空间、跳过/无法访问数、耗时。

### 3.4 保留策略引擎 F-04（用户最关心的「多样化选择」）

**设计原则：用户选「保留哪一份」，系统自动把其余标记为删除。** 比「选删哪一份」更符合直觉，也天然保证每组至少留一份。

**可用规则维度（每条规则可设升序/降序，即取「最长/最短、最新/最旧」）**

| 类别 | 规则 | 说明 |
| --- | --- | --- |
| 名称 | 文件名长度（短/长） | 字符数；中文按字符计，提供按字节切换 |
| 名称 | 文件夹名长度（短/长） | 直接父目录名 |
| 路径 | 完整路径长度（短/长） | 常用于「保留浅层目录」 |
| 路径 | 路径层级深度（浅/深） | 与长度不同，避免长文件名干扰 |
| 时间 | 创建时间（新/旧） | 优先用创建时间，其次修改时间 |
| 时间 | 修改时间（新/旧） | 注意复制会刷新，UI 需提示 |
| 位置 | 所在磁盘 / 指定优先目录 | 例：优先保留 D:\工作盘，清掉 E:\备份盘 |
| 位置 | 路径含关键字 / 正则 | 例：路径含「归档」「备份」「临时」「微信接收」的优先删除 |
| 名称 | 文件名含「副本/(1)/copy/最终版」 | 内置常见副本命名识别，作为降权项 |
| 属性 | 只读、隐藏、系统属性 | 默认降权（不优先保留/不优先删除，可配） |
| 安全 | **受保护路径** | 用户锁定的目录永远保留，规则链不可覆盖 |

**规则链机制**
1. 用户把多条规则拖入列表并排序，例如：`① 优先保留 D:\市场部 → ② 路径层级更浅 → ③ 修改时间更新 → ④ 文件名更短`。
2. 组内按规则逐条淘汰：第 ① 条若只剩一个候选即定案；若并列则进入第 ② 条，依次类推。
3. **平局兜底（关键防呆）**：所有规则用完仍有多个并列候选 → **不自动选择**，标记为「需人工确认」，默认保留全部、不加入删除队列。绝不用字典序偷偷删文件。
4. 提供「策略预演」：应用规则后先看统计（将删 X 个文件、释放 Y MB、按磁盘/目录分布），确认后才真正标记。
5. 策略可保存为模板（如「清备份盘模板」「留最新版模板」），一键复用。
6. 支持人工覆盖：任意组内可手动改「保留项」、把某个文件「锁定（永不删除）」、或整组「跳过」。

### 3.5 批量删除与安全防护 F-05
**安全是本产品第一优先级，任何便捷性都不能越过以下防线：**

1. **N−1 铁律**：每组最多删除 N−1 个，主保留项被锁定；系统在提交前二次校验。
2. **默认进回收站**：调用 Windows Shell 回收站接口（`SHFileOperation` / `Microsoft.VisualBasic.FileIO.FileSystem.DeleteFile` + `RecycleOption.SendToRecycleBin`），保留原路径以便还原。
3. 「永久删除」为高级选项：需勾选 + 输入确认词 + 明确警告文案，**且默认关闭**。
4. **删除前预演页**：列出将删除的完整路径清单（可导出 CSV/TXT）、总释放空间、受保护项、跳过项（占用/只读/权限不足/回收站不可用）。
5. **二次确认弹窗**，含不可逆提示与备份建议。
6. **操作日志**：每次执行生成一份 JSON/CSV 记录（时间、组 ID、指纹、原路径、回收站状态、执行结果），本地保存于 exe 同目录 `logs/`。
7. **一键还原**：从日志中选择某次操作，把回收站中的文件还原到原路径；若原路径已被占用，提示冲突并允许另存。
8. **执行期二次校验**：删除前重新核对文件大小 + 时间戳（或重算哈希开关），若组内文件自扫描后被改动 → 自动跳过该文件并提示。
9. 删除过程分批提交、可暂停/取消；单个文件失败不阻断整体，最后汇总失败清单。
10. **删除不等于释放空间的例外**：NTFS 硬链接、卷影副本、云占位文件会在报告中单独标注（见 9.1）。

### 3.6 交互流程 F-06（三步向导）
```
[1 选范围] → [2 扫描中] → [3 分组与处理] → [4 预演确认] → [5 完成报告]
```
- 第 1 步：目录/磁盘选择、排除规则、判定模式、文件大小阈值。
- 第 2 步：分阶段进度（枚举 → 大小分桶 → 采样 → 全量哈希 → 逐字节校验），显示当前文件、速度、剩余估算，支持暂停/取消/后台。
- 第 3 步：重复组表格 + 右侧「保留策略」面板；应用策略后有明显的「保留（绿）/ 待删除（灰红）/ 需确认（黄）」三态标识。
- 第 4、5 步：预演、确认、结果报告（释放空间实测值、失败项、还原入口）。

### 3.7 性能与工程 F-07
- 枚举与哈希分离，生产者/消费者队列；IO 线程与 CPU 线程数可配置（默认 = 物理核心数，上限 8，避免机械盘抖动）。
- 同一目录下的大文件优先并行、机械盘自动降级为串行（可检测磁盘类型或由用户选择）。
- 大文件（>1 GB）分块流式读取，避免内存暴涨；内存占用目标 < 500 MB。
- **结果缓存**：SQLite 本地库保存 `路径 + 大小 + 修改时间 + 指纹`，下次扫描只对新增/变更文件重算，实现增量扫描。
- **断点续扫**：扫描进度持久化，崩溃或取消后可从断点继续。
- 支持超过 260 字符的长路径（应用清单声明 `longPathAware`），Unicode/中文/空格/特殊字符文件名完整支持。
- 结果集用虚拟列表（VirtualMode），10 万行不卡顿。
- 全程纯本地：无网络请求、无遥测、无文件上传、无云端哈希库，可作为对外宣传点。

## 5. 技术方案建议（给开发的选型结论）

**推荐方案：.NET 8 / 9 + WinForms（或 WPF）+ self-contained single-file publish**

| 理由 | 说明 |
| --- | --- |
| 双击即用 | `PublishSingleFile=true` + `SelfContained=true`，用户无需安装 .NET 运行时；Windows 10 1607+ 原生支持 |
| 回收站原生 | .NET 内置 `Microsoft.VisualBasic.FileIO.FileSystem`，无需手写 COM，行为与资源管理器一致 |
| 表格性能 | WinForms `DataGridView` 虚拟模式可轻松承载十万行；中文渲染、DPI 支持成熟 |
| IO 与哈希 | `System.IO` + `System.Security.Cryptography.SHA256` 流式分块；`FileStream` 支持 >4GB 与长路径 |
| 许可 | .NET / WinForms 为 MIT 许可，商用风险与 Apache-2.0 同量级；SQLite（public domain / MIT）作缓存 |
| 交付 | `dotnet publish -r win-x64 -p:PublishSingleFile=true`，产出单个 exe + 可选的 pdb |

**备选方案对比**

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| Go + Wails（WebView2） | 单文件 ~15 MB、界面现代、并发强 | WebView2 依赖在低版本 Win10 可能缺失，需引导安装；GUI 逻辑用前端技术栈 | 次选，适合追求体积与现代 UI |
| Python + PyInstaller + tkinter | 开发最快 | 体积 60 MB+、扫描性能弱、杀软误报率高；PyQt 为 GPL 有商用风险 | 不推荐做正式产品，可做原型 |
| C++ / Win32 原生 | 体积最小、性能最好 | 开发成本高、UI 与表格需自研 | 仅在极致性能诉求下考虑 |

**明确排除**：任何引入 GPL/LGPL 依赖的组合（PyQt、Qt、部分压缩库），避免与「商用安全」的选型原则冲突。

**实现要点清单**：长路径 manifest、reparse point 检测（`FileAttributes.ReparsePoint`）、硬链接计数（`GetFileInformationByHandle` / `fsutil` 思路）、云占位属性检测、回收站删除、写前日志、取消令牌贯穿全流程。

## 7. 验收标准与测试用例

| 编号 | 用例 | 期望结果 |
| --- | --- | --- |
| T-01 | 两文件同内容、不同名、不同目录 | 合并为 1 组，匹配依据显示 L4 强一致 |
| T-02 | 两文件同名同大小但内容差 1 字节 | **不成组**，出现在「同名冲突」视图 |
| T-03 | 同内容文件 4 份，规则链「优先 D:\市场部 → 路径更浅 → 时间更新」 | 精确保留 1 份，其余 3 份进删除候选 |
| T-04 | 规则链全部并列（同长度、同时间、同深度） | 标记「需人工确认」，**不自动删除任何文件** |
| T-05 | 用户手动锁定某文件 | 该文件永不进删除队列，规则链不可覆盖 |
| T-06 | 删除执行中某文件被其他程序占用 | 跳过该文件并计入失败清单，其余继续 |
| T-07 | 删除后点击「还原本次操作」 | 文件回到原路径，内容不变 |
| T-08 | 扫描目录含符号链接指向盘符根目录 | 不跟随、不循环、记录为已跳过 |
| T-09 | NTFS 硬链接两个路径指向同一数据 | 单独标记「硬链接」，提示删除不释放空间 |
| T-10 | 扫描到 300 字符长中文路径 | 正常枚举、正常分组、不报 PathTooLong |
| T-11 | 100 万文件盘，扫描中点「取消」 | 3 秒内响应，无残留线程，进度可续 |
| T-12 | 断网环境运行 | 功能完全正常，无任何外联请求 |
| T-13 | 全新 Win10 纯净虚拟机双击 exe | 无需装运行时、不弹 UAC，直接出现主界面 |

**发布门槛**：T-01、T-02、T-04、T-05、T-07、T-13 必须 100% 通过；任何「误删不可还原」缺陷为阻断级。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 9.1 NTFS 硬链接 / 卷影 / 云占位 | 删了副本但空间不释放，用户认为软件无效 | 检测并单独标记，报告中区分「逻辑冗余」与「实际可释放空间」 |
| 9.2 哈希碰撞 | 理论上的误判 | 严格模式强制 L4 逐字节比对；关闭时明确标注置信度 |
| 9.3 用户误配规则（如「优先删最新」） | 批量删掉刚整理的文件 | 预演页 + 二次确认 + 回收站 + 一键还原，四层兜底 |
| 9.4 扫描后文件被改动 | 删错版本 | 提交前重校验大小/时间戳，变更即跳过 |
| 9.5 系统目录 / 程序目录被误清 | 软件或系统损坏 | 默认排除 + 解除需二次确认 + 只读/系统属性降权 |
| 9.6 杀软误报 / SmartScreen 拦截 | 用户不敢双击 | 代码签名、公开校验值、说明「纯本地不联网」 |
| 9.7 机械盘全量哈希过慢 | 体验差 | 大小分桶 + 三段采样 + 磁盘类型自适应并发 + 增量缓存 |
| 9.8 回收站被禁用或容量不足 | 删除失败或静默永久删除 | 执行前检测，失败即跳过并提示，绝不回退为静默永久删除 |

## 10. 待产品负责人确认的 3 个问题

1. **交付形态**：确认「单个 exe 绿色免安装」（体积略大但最省事），还是接受「exe + 同目录配置/日志文件夹」？（日志与缓存总要落地，建议后者）
2. **扫描范围默认值**：首次启动是否默认扫描「用户文档/下载/桌面」，还是必须由用户手动指定？（安全上建议后者）
3. **是否需要命令行 / 计划任务**：若只给非技术同事用，v1.0 可不做，留给 v1.1。
